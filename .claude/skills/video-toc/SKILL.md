# 動画の目次作成 (fcpxml のピン → YouTube チャプター)

## デフォルトの形式

```
00:00 OP
<1つ目のアイキャッチ> 1人目
<2つ目のアイキャッチ> 2人目
...
<最後のアイキャッチ> ED
```

- 先頭には必ず `00:00 OP` を付ける (YouTube のチャプターは 00:00 始まりでないと有効にならない)。
- **目次を付ける場所はアイキャッチ** (ピンと組になった所)。時間順に `1人目`, `2人目`… と番号を振る (見出しは人が付け直す前提の仮ラベル)。
- **最後の目次は ED** (最後のアイキャッチ = ED ムービーの入口)。その後ろに打たれたピン (「ED」など) は目次にしない。
- 時刻は FCP のタイムラインのタイムコード表示 (NDF) に合わせ、秒未満は切り捨て。1時間を超える動画は `h:mm:ss`。

## 手順

1. 渡されたファイルのパスを確認する (例: `~/Downloads/xxx.fcpxmld.zip`)。
2. このスキルフォルダ内の `scripts/fcpxml_toc.py` を実行する (zip のままでよい。展開は一時ディレクトリで行われる):

   ```bash
   python3 -I <このスキルのフォルダ>/scripts/fcpxml_toc.py "<入力パス>" --debug
   ```

   - `--label "{n}人目"`: 見出しを変える ({n} が通し番号。例: `"{n}組目"`)
   - `--project <名前>`: ライブラリ内にプロジェクトが複数ある場合に指定
   - `--no-op` / `--no-ed`: OP / ED を付けない
   - `--time-basis eyecatch|pin`: 目次の時刻 (既定 eyecatch)。`--timecode auto|real`: タイムコード(NDF)換算 (既定 auto)
   - `--eyecatch <名前>`: アイキャッチと見なすクリップ名の一部 (既定 `アイキャッチ`)
   - `--no-eyecatch`: アイキャッチを使わず、従来どおりピンだけで作る
   - `--tolerance <秒>`: アイキャッチ終了後この秒数以内のピンを組の相手とする (既定 10)
3. 確認する:
   - stderr に出るピンの総数と、ユーザーが言った人数 + 1 (ED) が合うか。合わなければ黙って調整せず、`--debug` の出力 (マーカー名・クリップ名) を添えてユーザーに確認する。
   - ED が全長の終わり近くにあるか。
   - stderr の `# ピンのつけ忘れ候補` / `# 参考:` / `# 警告:` は、結果と一緒に必ずユーザーに伝える。
4. 結果をコードブロックで返す (`--debug` の括弧部分は除く)。

## 目次の決め方 (アイキャッチ=場所 / ピン=組の確認)

2026-10-13 に公開済み動画 5 本 (A6・A8・A10・A12・A19) の概要欄チャプターを正解にして評価し、仕様を決めた
(評価ハーネス = `~/.claude/skills/video-toc-workspace/eval/run_eval.py`、回帰テスト = `…/tests/test_toc.py`)。

- 目次の場所 = 名前に `アイキャッチ` を含むクリップ (例: わむうアイキャッチ)。アイキャッチ終了 -0.5秒〜+10秒 (YouTube チャプターの最短間隔) にあるピンが組の相手。
- **目次の時刻 = アイキャッチの終わり** (`--time-basis eyecatch`・既定)。公開済み 5 本と最も一致する。ピンはアイキャッチの終わりの 1 秒前後にずれて打たれることがあり (A6 で実例)、ピンの位置を使うと 1 秒ずれる。`--time-basis pin` でピンの位置に切り替え可。
- **タイムコード換算**: 59.94/29.97/23.976p を NDF で表示すると、タイムコード秒は実時間より 0.1% 遅れる (25 分で約 1.5 秒)。目次は FCP のタイムコードを見て打つので、既定でそれに合わせる。DF・整数フレームレートは実時間のまま。`--timecode real` で実時間に戻せる。
- 相方のピンが無いアイキャッチは「つけ忘れ」。目次には載せ、stderr に `# ピンのつけ忘れ候補` と出る。必ずユーザーに伝える。
- **アイキャッチと組でないピンは目次に載せない** (stderr の `# 参考:` に出る)。公開済み動画では、人がアイキャッチ無しで足した区切りが一部あり (A8 の「着用感レビュー」など)、構造からは予測できない。載せたい場所があれば、ユーザーに教えてもらう。
- チャプターマーカー (オレンジ) かどうかは目安にならない (公開側と一致しなかった)。
- アイキャッチのクリップが1つも見つからない時は、従来どおりピンだけで作る (警告が出る)。最後のピンが ED。
- プロジェクトが複数ある時は「アイキャッチを含む > 名前が 本編 > 長い」の順で自動選択 (サムネ・物撮りを避ける)。`--project` で上書き。
- YouTube で有効なチャプターの条件 (3 個以上・各間隔 10 秒以上) を満たさない時は警告が出る。
- アイキャッチは spine と接続クリップを辿って探す。複合クリップ (ref-clip) の中は拾わない。

## 仕組みのメモ

- マーカーは素材クリップ側 (マルチカムクリップ等) に付いているため、同じマーカーが XML 内に何百回も出てくる。スクリプトは project の spine を辿り、各クリップの使用範囲 (`start`〜`start+duration`) に入っているマーカーだけを `offset` を使ってタイムライン時刻に変換する。
- 素材内のマーカー番号 (「マーカー 1」など) とタイムライン上の順番は一致しないことがある。順番は必ずタイムライン時刻で決める。
- 複合クリップ (ref-clip) の中身 (resources 側) に付いたマーカーは拾わない。ピンが足りないときはそこを疑う。
