## 5. 手順書: 新作紹介型の作り方（10/12 撮影の縦素材から）

1. **素材を並べる**: 縦の映像と音声（ピンマイク・WAV）をマルチカム（「カメラ」「音声」）にする。新しいプロジェクトは 1080×1920・59.94p・48kHz。商品が複数なら 1 つのプロジェクトに並べてよい（間を 3〜5 秒あける）。
2. **文字起こし**: faster-whisper（medium、`scratchpad/shorts/scripts/asr.py`）で起こし、「つかみ・悩み・宣言・特徴・身長・価格・発売日」に印を付ける。時刻はマルチカムの時刻に合わせる（shiun-transcript-time-check）。
3. **どこを使うか**: 長さ 1 品 70〜95 秒にする。並べ方は【つ】結論 1 文（3 秒以内）→【悩】11〜24 秒→【宣】「〜を作りました」→【名】→【特】3〜5 個→【着】→【表】→【価】→【発】。撮り順と違っても、つかみに使える結論の 1 文（「低身長が〜時代を終わらせます」「低身長でも〜で着られる」）を頭に持ってくる。発売日の言い間違いがあればテロップで直す。
4. **ジェットカット**: 1 カット 0.65 秒くらい（1 分 77 カット）まで詰める。言いかけ・「えー」・無音は残さない。
5. **字幕**: 全部の発言に 1 行 11 字前後（最大 18）で切る。頭と終わりを本線の編集点に合わせ、すき間 0 でつなぐ。書式は 4-2 の表のまま（基本タイトル・Klee 28・`0 -432.992`・変形 `0 3.7037`）。つかみ・締めだけ Klee 35、強調の 1 語は Klee 40。「子供」→「子ども」（Slack 02-19）、ローマ字の打ち残しなし。
6. **インサート**: 話している部位が見える画を当てる（リブ・ボタン・生地の寄り・全身）。画面に出ている割合 50〜80%。インサートの音は消す。
7. **商品の情報**:
   - 商品名カード: `商品名 / Color : 全色 | Size : XS, S, M`（Color は展開色を全部、カンマ区切り）。【宣】の直後に 1.1〜3.6 秒、効果音つき。
   - 身長ラベル: `164cm / Size : S`（わむう）・`158cm / Size : XS` は必ず。4 人の早送りは 158・165・167・170（モデルの身長は元データで確認。165cm を 156cm と打った前例あり）。26Fall1st はわむうの着用サイズ M（Slack 08-24）など、回ごとに確認。
   - サイズ表: EC・中森さんの検寸と同じ数値、小数点も丸めない（shiun-size-table-telop）。
   - 価格カード: `¥ 14,300 - tax in`（¥ の後に半角スペース、`- tax in`）。
   - 価格・商品名・色は台本と EC で照合（shiun-price-name-check）。A24（26FW Winter 1st）の長編と同じ表記にする（6 章）。
8. **BGM**: Epidemic Sound の明るいインスト 1 曲を 0 秒から最後まで、−28dB（声が小さい素材なら −23dB）。最後 0.15 秒でフェードアウト。効果音は商品名・価格の頭だけ（shiun-bgm-check）。

## カットとインサートの精度（2026-10-13 ユーザー指摘）
- **子音の脱落・言い終わりの切れが起きやすい**。無声の子音（サ・シ・ス・ハ・フ・カ・キ・タ・ツ）は全体の音量では小さく、声の始まりより 50〜120ms 早く鳴る。また文末の「す」「た」は母音が抜けて息だけになる。
  - 始まりと終わりは、全体の音量と高い帯域（3〜8kHz）の音量のうち、早い始まり・遅い終わりで決める。
  - 頭の余白は 0.06 秒（無声の子音なら 0.10 秒）。
  - 尾の余白は 0.12 秒（文末なら 0.18 秒）。
  - 確かめは `editing/tools/cut_check.py edl.json マイクのフォルダ [--asr]` で、頭・尾の切れを 0 件にする。
- **インサートは文の切れ目で出し入れする**。「そんな〇〇に／なっています」のように、述語の直前でインサートが終わって本線に戻るのは不可（長尺で実際にあった）。1 つの文はひとつの画の上に置く。

## 渡す前に必ず FCP の決まりで検証する（2026-10-13 4 本とも FCP で読み込めなかった）
- `python3 editing/tools/validate_fcpxml.py 出力.fcpxml` が「OK」になるまで渡さない。XML として読めるかの確認だけでは足りない。
- 読み込めなかった原因は 3 つあり、どれも short_build.py で直した。
  1. BGM・効果音の asset-clip が参照する format（r76）を出力に写していなかった。
  2. mc-clip の中で、つないだタイトル・インサートより前に filter-audio を置いていた。DTD の順は「mc-source → つなぐ物 → filter-audio」。
  3. 画角を合わせる adjust-transform を mc-clip の直下に置いていた。mc-clip では、映像の mc-source の中に置く。
- 素材の format は記録されたとおりに書く（縦撮りの DSCF は 1920x1080、24.00p）。パスの日本語は % で書く。
- **素材の asset は実物どおりに書く**（再接続できなかった、2026-10-13）。DSCF の MOV は撮影時刻のタイムコードから始まる（例 DSCF0030 は 19:08:30:21）。頭を 0 秒にすると FCP が「メディアの範囲が異なる」と再接続を拒む。
  - 元の素材を FCP のイベントに入れ、イベントごと「書き出し → XML」してもらう。
  - `editing/tools/short_media_info.py` で media_info.json にし、edl の "media_info" に指定して short_build.py を回す。頭の時刻・長さ・チャンネル・uid・format・パスが実物と同じになる。
  - 縦撮りの DSCF は、FCP では 1080x1920・frameDuration 1000/24000s として読まれる。
- **24.00p の素材には conform-rate scaleEnabled="0" を付ける**（ピンマイクがずれて聞こえた、2026-10-13）。付けないと FCP が 59.94p のマルチカム・タイムラインで「自動速度」をかけ、映像を 23.976 に 0.1% 遅くする。音（マイク）は遅くならないので、素材の後ろほどずれる（300 秒で約 0.3 秒）。型（A23）も全素材に conform-rate scaleEnabled="0" を付けている。
- マルチカムのマイクの置き方は、offset を 59.94p のコマに揃え、端数は start（1/48000 秒）で持つ。
- **マルチカムのアングルの頭に空きがあるときは、gap を前に置く**（ピンマイクが 1.7 秒ずれて聞こえた、2026-10-13）。gap を置かずに asset-clip の offset だけで後ろへずらすと、FCP は波形をずらした位置に描く。ところが再生はアングルの頭から鳴らすので、波形と聞こえる音が offset のぶん食い違う。FCP の書き出し（型）も必ず「gap → asset-clip」の順になっている。
  - 書き出した動画の音をマイクと照らすと、ローファーはカットごとに一定で +1.685 秒ずれていた（＝マイクの offset 1.67 秒＋1 コマ）。
